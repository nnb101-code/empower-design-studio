# GlattTrack — חשמל, רשת ושרת חלופי במפעל

מטרה: **הפסקת חשמל, שרת שנשרף או מתג שנפל לא עוצרים את השחיטה ולא מאבדים פסיקה.**
המדריך מיועד למתקין (איש מחשבים). ראש הצוות לא צריך לעשות כלום, הוא רק רואה את המצב במסך **בריאות מערכת**.

> ⚠ עדיין לא למפעל אמיתי עד שסבבי הבדיקה יסתיימו.

---

## 1. התמונה בקצרה

```
             ┌──────── UPS ────────┐
 טאבלטים ── WiFi ── מתג ──┬── שרת A (ראשי)   192.168.1.11
 (כתובת אחת:              └── שרת B (גיבוי)  192.168.1.12
  192.168.1.10)
```

* **שני שרתים זהים, A ו-B.** כל שינוי ב-A עובר מיד ל-B.
* **הטאבלטים מכירים כתובת אחת בלבד (192.168.1.10).** הכתובת "צפה": היא תמיד אצל השרת הראשי. כשהשרת מתחלף אין צורך לשנות דבר בטאבלטים, וגם לא צריך כניסה מחדש.
* **פסיקה נשמרת בשני השרתים לפני שהטאבלט מקבל אישור.** אם A נשרף, אף פסיקה לא הולכת לאיבוד.
* **אם B נפל, העבודה לא נעצרת.** אחרי כ-6 שניות A ממשיך לבד, ומסך הבריאות מראה "שרת גיבוי: לא מחובר".
* **השרת הישן לא חוזר להיות ראשי לבד.** הוא חוזר רק כשרת גיבוי. כך אין אף פעם שני שרתים ראשיים עם שתי "אמיתות".

---

## 2. רשימת ציוד (חובה)

| מה | למה | הערה |
|---|---|---|
| **UPS** לשרת A, לשרת B, למתג ולנקודות הגישה (WiFi) | הפסקת חשמל לא מפילה את הרשת | לפחות 30 דקות. חיבור USB לשרת A (וגם ל-B אם יש שני UPS) |
| **שני שרתים** (מחשב קטן מספיק: 8GB זיכרון, דיסק SSD) | אחד ראשי, אחד גיבוי | **כל אחד בארון / שקע אחר** אם אפשר |
| **שתי נקודות גישה WiFi** שמכסות את כל התחנות | אם אחת נופלת, הטאבלטים עוברים לשנייה | אותו שם רשת (SSID) ואותה סיסמה |
| **מתג (switch)** | מחבר שרתים ונקודות גישה | על ה-UPS |
| **דיסק חיצוני (USB)** בשרת A וגם בשרת B | גיבוי לילי שנבדק | הגיבוי נעשה בשרת שהוא הראשי באותו לילה |
| **נוהל חירום על נייר** בכל תחנה | אם הכל נופל | נוהל נפרד (בהכנה) |

**כתובות קבועות:** לשרת A, לשרת B ולכתובת הצפה, מחוץ לטווח ה-DHCP של הנתב.

## 3. התקנה (פעם אחת)

על **שני** השרתים:

```bash
sudo apt install postgresql-16 keepalived nut iputils-ping
sudo mkdir -p /opt/glatttrack /etc/glatttrack
sudo cp -r plant-server /opt/glatttrack/
sudo cp /opt/glatttrack/plant-server/gt-plant.conf /etc/glatttrack/gt-plant.conf
sudo nano /etc/glatttrack/gt-plant.conf     # GT_SELF, GT_SELF_IP, GT_PEER_IP ...
```

ב-`gt-plant.conf`, רק שלוש השורות הראשונות שונות בין A ל-B. את השאר (הכתובת הצפה, הסיסמה של `GT_REPL_PASS`, כתובת הנתב) כותבים זהה בשניהם.

### 3.1 שרת A (ראשי). GlattTrack כבר מותקן ועובד עליו

```bash
sudo /opt/glatttrack/plant-server/setup-primary.sh
sudo systemctl restart postgresql
```

### 3.2 שרת B (גיבוי)

```bash
sudo /opt/glatttrack/plant-server/setup-standby.sh --yes
```

הפקודה **מוחקת** את מסד הנתונים של B ומעתיקה את כולו מ-A. בסוף צריך להופיע `standby B: standby`.

### 3.3 הכתובת הצפה (keepalived), על שני השרתים

```bash
sudo cp /opt/glatttrack/plant-server/keepalived/keepalived-A.conf /etc/keepalived/keepalived.conf   # ב-B: keepalived-B.conf
sudo nano /etc/keepalived/keepalived.conf    # interface, כתובות, auth_pass (זהה בשניהם)
sudo systemctl enable --now keepalived
```

### 3.4 שומר הסנכרון והגיבוי הלילי, על שני השרתים

```bash
sudo cp /opt/glatttrack/plant-server/systemd/* /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now gt-sync-watchdog.service gt-backup.timer
```

### 3.5 UPS (NUT), על כל שרת שה-UPS מחובר אליו ב-USB

מגדירים את NUT לפי סוג ה-UPS (`/etc/nut/ups.conf`), ומוסיפים ל-`/etc/nut/upsmon.conf` את השורות מ-`nut/upsmon-snippet.conf`.
בסוללה נמוכה השרת נכבה מסודר. אם זה הראשי, הגיבוי ממשיך, בתנאי שה-UPS שלו מחזיק.

### 3.6 בדיקה שהכל עובד

במסך **בריאות מערכת** של ראש הצוות צריך לראות:

* 🟢 **שרתים**: `שרת A · שרת גיבוי: מחובר`
* 🟢 **חשמל (UPS)**: `תקין` (אחרי אירוע UPS ראשון)
* 🟢 **גיבוי**: `מאומת לפני … שעות` (אחרי הלילה הראשון, או אחרי הרצה ידנית של `backup.sh`)

## 4. מה קורה כש...

| מקרה | מה קורה לבד | מה רואים במסך הבריאות | מה עושים |
|---|---|---|---|
| **הפסקת חשמל** | הכל ממשיך על ה-UPS | 🔴 חשמל: על סוללה — אין חשמל | להכין את נוהל הנייר אם החשמל לא חוזר |
| **סוללה נמוכה** | השרתים נכבים מסודר | 🔴 סוללה כמעט ריקה | לעבור לנוהל הנייר |
| **שרת B נפל** | A ממשיך לבד אחרי כ-6 שניות. פסיקה אחת עלולה לחכות עד 6 שניות | 🔴 שרתים: שרת גיבוי לא מחובר | לתקן את B. כשהוא חוזר, הסנכרון חוזר לבד |
| **שרת A נפל** | B הופך לראשי תוך כ-5–10 שניות, והכתובת הצפה עוברת אליו. הטאבלטים ממשיכים (נעילת "אין שרת" עד 15 שניות) | ℹ שרת הגיבוי החליף את הראשי | לתקן את A ולהחזיר אותו **כגיבוי** (סעיף 5) |
| **A חזר לבד אחרי שנפל** | A רואה ש-B הוא הראשי, **עוצר את עצמו** ולא מקבל את הכתובת | — | סעיף 5 |
| **הכבל של B נותק (B לא רואה את הנתב)** | B **לא** משתלט: "הבעיה אצלי, לא בראשי" | 🔴 שרת גיבוי לא מחובר | לחבר את הכבל |
| **נקודת גישה אחת נפלה** | הטאבלטים עוברים לשנייה | — | להחליף |
| **המתג נפל** | אין רשת. נעילת "אין שרת = אין עבודה" | — | מתג רזרבי במחסן. אם אין, נוהל הנייר |

## 5. החזרת שרת ישן כשרת גיבוי (אחרי החלפה)

על **השרת הישן** (למשל A, אחרי ש-B השתלט):

```bash
sudo /opt/glatttrack/plant-server/rejoin-as-standby.sh --yes
sudo systemctl restart keepalived
```

הפקודה מוחקת את הנתונים הישנים של השרת ומעתיקה את הכל מהראשי החדש. אחרי כמה שניות מסך הבריאות חוזר ל-🟢 **שרתים: שרת גיבוי מחובר**.
אחר כך השרתים נשארים כך: B ראשי ו-A גיבוי. **אין צורך** להחזיר את A להיות ראשי.

---

## 6. איך זה נבדק

כל המקרים מסעיף 4 נבדקו על שני שרתי PostgreSQL 16 אמיתיים:

* כתיבה ב-A נקראת ב-B.
* UPS: on battery, low battery, online.
* B כבוי: פסיקה לא נתקעת (חיכתה 4 שניות) ו-A ממשיך לבד.
* B חזר: הסנכרון חוזר.
* B סירב להשתלט כש-A חי, וגם כשלא ראה את הנתב.
* A נפל: B השתלט, הכניסה של ראש הצוות נשארה בתוקף, וכתיבה ב-B הצליחה.
* A עלה לבד: עצר את עצמו.
* A חזר כגיבוי וקיבל את מה שנכתב ב-B.
* גיבוי לילי נבדק בשחזור.

## 7. קבצים

| קובץ | מה הוא עושה |
|---|---|
| `gt-plant.conf` | ההגדרות של השרת. מעתיקים ל-`/etc/glatttrack/` |
| `setup-primary.sh` | פעם אחת, על הראשי |
| `setup-standby.sh --yes` | פעם אחת, על הגיבוי (מוחק ומעתיק) |
| `promote.sh` | keepalived מפעיל אותו כשהשרת מקבל את הכתובת. מסרב אם הראשי עוד חי או אם אין רשת |
| `rejoin-as-standby.sh --yes` | שרת ישן חוזר כגיבוי |
| `gt-sync-watchdog.sh` | רץ תמיד: סנכרון כשיש גיבוי, עבודה לבד כשאין, ועצירה עצמית של ראשי ישן |
| `ups-event.sh` | NUT מפעיל אותו. כותב את מצב החשמל למסך הבריאות |
| `backup.sh` | גיבוי לילי, נבדק בשחזור |
| `keepalived/` | הכתובת הצפה ובדיקת התקינות |
| `systemd/`, `nut/` | הפעלה אוטומטית |
