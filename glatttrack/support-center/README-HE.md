# מרכז השירות של היצרן — התקנה (v10.38)

מרכז השירות הוא מסך אחד שמציג את כל המפעלים. כל מפעל מופיע בקוביה עם נורה:
- **ירוק:** תקין.
- **כתום:** לטפל היום.
- **אדום מהבהב:** בעיה עכשיו. נשמע גם צליל, ונשלחת התראה.

כל שרת מפעל מדווח למרכז כל 5 דקות. מפעל שלא דיווח 15 דקות הופך לאדום, עם ההודעה "המפעל לא מדווח".

## 1. מסד הנתונים המרכזי (פעם אחת)
1. פותחים פרויקט Supabase **נפרד** של היצרן. זה לא מסד של מפעל.
2. ב-SQL Editor מריצים את `central-setup.sql`. ההרצה בטוחה גם יותר מפעם אחת.
3. מריצים את `central-selftest.sql`. בתוצאה (שורה אחת בטבלה למטה) צריך להיות `PASSED — 35 of 35`.
4. יוצרים את המנהל הראשון (את השאר מוסיפים אחר כך מהדף, בלשונית "צוות"):
   ```sql
   insert into sc_staff (name, code_hash, role) values ('שם המנהל', extensions.crypt('<קוד ארוך>', extensions.gen_salt('bf', 8)), 'admin');
   ```

## 1א. עדכון מרכז שכבר מותקן
1. ב-SQL Editor של פרויקט היצרן מריצים שוב את `central-setup.sql` (כל הקובץ). זה בטוח: שום מפעל, איש צוות או חיוב לא נמחק.
2. מריצים את `central-selftest.sql` → `PASSED — 35 of 35`. הבדיקה לא משנה כלום.
3. הדף (`index.html`) צריך החלפה רק כשהוא השתנה. בעדכון של 19.10 (סבב 3) הוא לא השתנה.

## 1ב. שכחתי את הקוד · I forgot my code
קוד נשמר רק מוצפן. אי אפשר לראות אותו, אפשר רק לקבוע קוד חדש. · A code is kept only encrypted: it can't be seen, only replaced.
- **קוד שחזור (למנהל):** בלשונית "צוות" ← "🛟 קוד השחזור שלי" ← "צור קוד שחזור חדש". הקוד מוצג **פעם אחת**. כותבים אותו על דף ושומרים בכספת. אם שוכחים את הקוד: במסך הכניסה ← "שכחתי את הקוד" ← קוד השחזור + קוד חדש. קוד שחזור עובד פעם אחת, ואחרי השימוש יוצרים חדש. · **Recovery code (admins):** Staff → My recovery code → make a new one. It is shown **once**; keep it on paper in a safe. On the login screen → "I forgot my code".
- **מנהל אחר:** בלשונית "צוות" ← "🔑 קוד חדש" ליד השם. · **Another admin:** Staff → "🔑 New code" next to the name.
- **בלי שניהם:** ב-SQL Editor מריצים · **Without either:** in the SQL Editor:
  ```sql
  update sc_staff set code_hash = extensions.crypt('קוד-חדש-לפחות-10-תווים', extensions.gen_salt('bf', 8)), active = true where name = 'השם';
  ```
- **שדה הקוד** כתוב משמאל לימין. 👁 מציג את הקוד ל-30 שניות. אם המקלדת בעברית, מופיעה אזהרה. · The code field is left-to-right; 👁 shows it for 30 s; a warning appears if the keyboard is Hebrew.
- **שפה:** הכפתור "עב | EN" למעלה. · **Language:** the "עב | EN" button at the top.

## 1ג. קוד יצרן חדש למפעל (כפתור "Maker" באפליקציה של המפעל) · A new manufacturer code for a plant
1. בדף: מפעל ← **🔑 קוד יצרן חדש למפעל הזה**. כותבים את הקוד פעמיים ← **⬇ הכן בקשה**. יורד קובץ `maker-code-<מספר>.json`. הקוד עצמו לא נמצא בקובץ, יש בו רק "טביעת אצבע" מוצפנת. · In the page: plant → **🔑 New manufacturer code** → type it twice → **Make the request**. A file downloads. The code itself is not in it.
2. במחשב של היצרן, שבו המפתח הסודי: `bash maker-code-sign.sh maker-code-<מספר>.json`. נוצר `maker-code-<מספר>.signed.json`. · On the manufacturer's computer: sign it.
3. בדף: בוחרים את הקובץ החתום ← **שלח למפעל**. · In the page: choose the signed file → **Send to the plant**.
4. המפעל בודק את החתימה, את מספר המפעל ואת הזמן (עד 7 ימים), ומחליף את הקוד בדיווח הבא (עד 5 דקות). התוצאה מופיעה ב"פקודות". · The plant checks the signature, plant number and time, and changes the code at its next report.

## 1ד. רישיונות · Licenses
- **מחלקה:** "רישיונות ומכירות" רואה ויוצרת רישיונות, ותו לא. בלי מפעלים, בלי כספים ובלי צוות. · **Department:** "Licenses and sales" sees and creates licenses only.
- **פעם אחת לכל מפעל:** לשונית 🔑 רישיונות ← **🔑 מפתח למפעל**. מקבלים שורת SQL אחת, ומריצים אותה ב-SQL Editor של ה-Supabase **של המפעל**. · **Once per plant:** 🔑 Licenses → **Plant key** → run the SQL line in the **plant's** Supabase.
- **רישיון חדש:** בוחרים תקופה (דמו 14 / 30 יום, חודש, חודשיים, חצי שנה, שנה, או עד תאריך) ומספר טאבלטים. נוצר קוד `GT-…`. · **New license:** choose the period and number of tablets; a `GT-…` code is made.
  - יש שרת מפעל: הקוד מגיע לבד בדיווח הבא. · With a plant server: it arrives by itself at the next report.
  - אין שרת מפעל: ראש הצוות מקליד את הקוד בהגדרות ← מערכת ← רישיון. · Without one: the team leader types it in Settings → System → License.
- **כשרישיון נגמר:** · **When a license ends:**
  - 14 יום לפני: אזהרה במסכים, והתראה אליך (גם 7 ימים ויום אחד לפני, ובסוף). · 14 days before: a warning on the screens and alerts to you (also 7 days and 1 day before, and at the end).
  - אחרי הסוף: **2 ימי חסד.** · After the end: **2 grace days.**
  - אחר כך יום שחיטה **חדש** לא נפתח. אף פעם לא באמצע יום, והנתונים והסיכומים נשארים פתוחים. · Then a **new** slaughter day doesn't open — never mid-day; data and summaries stay open.
- **מפעל בלי רישיון:** דמו של 30 יום מההתקנה. · **A plant without a license:** a 30-day demo from installation.

## 2. דף מרכז השירות
1. מעלים את `index.html` לאתר של היצרן. מומלץ להגן עליו ב-https.
2. לידו שמים את `sc-config.js`, עם הכתובת והמפתח הציבורי (anon) של הפרויקט:
   ```js
   window.SC_SERVER = { url: 'https://<project>.supabase.co', anonKey: '<anon key>' };
   ```
3. נכנסים עם הקוד של עובד השירות.
4. **בטלפון, או בלי אתר:** פותחים את `glatttrack-center.html` מתיקיית ההעלאה. זה אותו דף, והכתובת והמפתח הציבורי כבר בתוכו, אז אין צורך בקובץ שני. אם נפתח `index.html` בלי `sc-config.js` לידו, מופיעה ההודעה "חסרה כתובת השרת". · **On a phone, or without a website:** open `glatttrack-center.html` from the upload folder. It is the same page with the address and the public key inside, so no second file is needed.

## 3. מפעל חדש
1. בדף: "עדכונים והגדרות" ← "מפעל חדש" ← מספר ושם. (רק מנהל.)
2. **הסוד של המפעל מוצג פעם אחת בלבד.** מעתיקים אותו לקובץ `gt-plant.conf` בשרת המפעל:
   ```
   GT_CENTER_URL=https://<project>.supabase.co
   GT_CENTER_KEY=<anon key>
   GT_PLANT_CODE=1007
   GT_PLANT_SECRET=<הסוד>
   GT_STANDBY_RESTART_CMD=...   (לא חובה — מאפשר "הפעל מחדש את שרת הגיבוי" מרחוק)
   GT_APP_FILE=/var/www/glatttrack/index.html
   ```
3. בשרת המפעל מפעילים את הדיווח:
   ```
   sudo cp plant-server/systemd/gt-report.* /etc/systemd/system/
   sudo systemctl enable --now gt-report.timer
   ```

## 4. התראות: מייל, SMS, וואטסאפ — כל אחד לבחירה
- **בדף:** "הגדרות" ← "התראות". לכל ערוץ מסמנים "פעיל", כותבים כתובות, ובוחרים מאיזו רמה לשלוח: רק אדום, או גם כתום.
- **השליחה עצמה:** `notify.sh`, שרץ כל דקה (cron) על מחשב של היצרן:
  1. מעתיקים את `notify.env.example` לקובץ `notify.env` ומגבילים את ההרשאות שלו (`chmod 600`).
  2. ממלאים בו:
     - כתובת המסד;
     - פרטי שרת המייל (SMTP);
     - חשבון Twilio, ל-SMS ולוואטסאפ. לוואטסאפ צריך גם שולח מאושר ב-Twilio.
  3. מוסיפים ל-cron: `* * * * * /opt/glatttrack/support-center/notify.sh`
- כל התראה נשלחת פעם אחת. אם ערוץ נכשל, הוא ינסה שוב בדקה הבאה.

## 5. עדכון לכל המפעלים, בלי אישור של ראש צוות — רק עדכון חתום
**למה חתימה:** עדכון כולל גם קוד שרת (02) שרץ במפעל בהרשאות מלאות. החתימה מבטיחה שרק היצרן יכול לשלוח עדכון. גם מי שנכנס למרכז השירות (או גנב קוד של איש תמיכה) לא יכול לשלוח קוד משלו: המפעל לא יתקין אותו.

**פעם אחת — מפתח החתימה:**
1. במחשב של היצרן (לא במרכז השירות ולא בשרת מפעל): `bash release-key-new.sh`
2. נוצרים שני קבצים:
   - `gt-release-private.pem` — **סודי.** נשאר במחשב הזה. עותק גיבוי אחד על דיסק-און-קי בכספת. לעולם לא מעלים אותו לשום מקום.
   - `gt-release-public.pem` — מעתיקים לכל שרת מפעל: `/etc/glatttrack/release-public.pem`. בלי הקובץ הזה המפעל לא מתקין שום עדכון.

**כל עדכון:**
1. **חותמים** במחשב של היצרן: `bash release-sign.sh v10.39 kosher-app.html [02.sql]`. נוצר `release-v10.39.signed.json`. בקובץ: הגרסה וה-sha256 של כל קובץ, והחתימה.
2. **מעלים את הקבצים** (האפליקציה, ואם יש, גם 02) לכתובת https.
3. **שולחים:** בדף, "עדכונים והגדרות" ← "שלח עדכון לכל המפעלים" ← בוחרים את הקובץ החתום ← כותבים את הכתובות.
4. **מה כל מפעל עושה בדיווח הבא:**
   1. בודק את החתימה במפתח הציבורי של היצרן. חתימה חסרה או לא נכונה — לא מתקין (ומנסה שוב רק אחרי 6 שעות).
   2. מוריד את הקבצים, ובודק שה-sha256 שלהם הוא בדיוק מה שנחתם.
   3. מריץ את 02, ואחריו את בדיקת האבטחה (03).
   4. רק אם הבדיקה עברה, מחליף את קובץ האפליקציה. אחרת שום דבר לא משתנה.
   - עדכון עם חלק שרת (02) מותקן רק כשאף אחד לא עובד.
   - **אם המפתח הסודי נגנב:** יוצרים מפתח חדש, ומחליפים את `release-public.pem` בכל המפעלים (ביד, במפעל עצמו). את המפתח הישן מוחקים מיד — אסור להשאיר אותו גם לא כ"הבא".
   - **החלפת מפתח מתוכננת (המפתח לא נגנב):**
     1. יוצרים מפתח חדש: `bash release-key-new.sh` בתיקייה אחרת, כדי לא לדרוס את הישן.
     2. מעתיקים את המפתח הציבורי **החדש** לכל מפעל: `/etc/glatttrack/release-public-next.pem`, ומדליקים ב-`gt-plant.conf` את השורה `GT_RELEASE_PUBKEY_NEXT`. עכשיו כל מפעל מקבל עדכון חתום בישן **או** בחדש.
     3. מהיום חותמים רק במפתח החדש.
     4. כשכל המפעלים קיבלו את החדש: בכל מפעל מעבירים את החדש ל-`release-public.pem`, מוחקים את `release-public-next.pem`, ומכבים שוב את השורה. את המפתח הסודי הישן מוחקים.
5. **הטאבלטים:**
   - טאבלט שלא בשימוש מתעדכן מיד.
   - טאבלט בשימוש שואל "לעדכן עכשיו / אחר כך". אחרי 10 דקות בלי שימוש, הוא מתעדכן לבד.
   - לפני העדכון, כל מה שנלחץ נשלח לשרת. אחרי העדכון, הטאבלט חוזר לאותו מסך ולאותו עובד.
6. **חזרה לגרסה הקודמת:** בשרת המפעל מריצים `plant-server/update-app.sh --rollback`.
   - **זה מחזיר רק את האפליקציה.** השינוי בשרת (02) נשאר.
   - **לכן הכלל:** כל 02 חדש חייב לעבוד גם עם האפליקציה של הגרסה הקודמת. לא מוחקים ולא משנים פונקציה שהאפליקציה הקודמת קוראת לה, ולא מוסיפים חובה שהיא לא שולחת. מה שישן מקבל ערך ברירת מחדל.
   - **לפני כל חתימה של עדכון עם 02:** מריצים את בדיקות הדפדפן של הגרסה הקודמת מול 02 החדש (במסד בדיקה), ורק אם הן עוברות, חותמים.

## 6. הלשוניות והתפקידים (v10.38)
| לשונית | מה יש בה |
|---|---|
| 🏭 מפעלים | כל המפעלים עם נורה. בדף של מפעל: מצב, טאבלטים, פקודות, התקלות שלו, והחיוב של החודש. |
| 🛠 תקלות | כל דיווח בעיה ממסך במפעל, וכל דיווח של ראש צוות. "קח לטיפול" ← "טופל", ותשובה למפעל. |
| 💰 חיובים | לכל מפעל, לבחירה: לפי ק"ג, לפי בהמה, או סכום חודשי קבוע. אפשר מינימום חודשי ומטבע. סימון "שולם". ייצוא ל-Excel. |
| 👥 צוות | הוספת אנשי צוות עם תפקיד, השבתה, ויומן "מי עשה מה". |
| ⬆ עדכונים והגדרות | התראות, מפעל חדש, שליחת גרסה לכל המפעלים. |

| תפקיד | מה רואה | מה יכול לשנות |
|---|---|---|
| מנהל | הכל | הכל |
| תמיכה טכנית | מפעלים, תקלות, עדכונים | תקלות, פקודות, התראות, עדכונים. בלי חיובים ובלי צוות. |
| כספים | חיובים בלבד | חיובים ו"שולם" |
| צפייה בלבד | מפעלים, תקלות, חיובים | כלום |

- **אי אפשר להסיר את המנהל האחרון.** קוד כניסה: לפחות 10 תווים.
- **הכמויות לחיוב** מגיעות מהמפעל עצמו: כמה בהמות נשחטו וכמה ק"ג נשקלו בכל יום (40 הימים האחרונים, בכל דיווח).
- **התקלה חוזרת למפעל:** ראש הצוות רואה בלשונית "תקלות" את המצב (נשלח / בטיפול / טופל) ואת התשובה.
- **מה היצרן שינה:** ראש הצוות רואה בלשונית "תקלות" כל שינוי שהיצרן עשה במפעל.

## מה נשלח למרכז, ומה לא
- **נשלח:** מצב השרתים, גיבוי, בדיקת הלילה, יומן האירועים (תקין או לא), כמה כניסות שגויות, האם עובדים עכשיו, ולכל טאבלט: מחובר או לא, ובאיזו גרסה.
- **נשלח מ-v10.38:** דיווחי הבעיה (מה כתוב בהם), וסכום יומי של בהמות וק"ג.
- **לא נשלח לעולם:** פסיקות, מספרי בהמות, קודים. שם עובד נשלח רק אם הוא כתב אותו בתוך הדיווח.
