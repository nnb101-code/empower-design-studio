# GlattTrack — חשמל, רשת ושרת חלופי במפעל (v10.16)

מטרה: **הפסקת חשמל, שרת שנשרף או מתג שנפל לא מאבדים פסיקה, ואף פעם אין שני שרתים ראשיים.**

המדריך מיועד למתקין (איש מחשבים). ראש הצוות לא צריך לעשות כלום, רק לראות את המצב במסך **בריאות מערכת**.

> ⚠ עדיין לא למפעל אמיתי עד שסבבי הבדיקה יסתיימו.

---

## 1. התמונה בקצרה

```
             ┌──────── UPS ────────┐
 טאבלטים ── WiFi ── מתג ──┬── שרת A (ראשי)   192.168.1.11
 (כתובת אחת:              └── שרת B (גיבוי)  192.168.1.12
  192.168.1.10)
```

* **שני שרתים זהים, A ו-B.** כל שינוי ב-A עובר מיד ל-B.
* **הטאבלטים מכירים כתובת אחת בלבד (192.168.1.10).** היא תמיד אצל **השרת הראשי, ורק אצלו.** שרת גיבוי אף פעם לא מחזיק אותה.
* **החלפת השרת הראשי לא קורה לבד (v10.16).** אדם בודק שהשרת הראשי באמת כבוי, ומריץ פקודה אחת. הסיבה מוסברת בסעיף 4.
* **השרת הישן לא חוזר להיות ראשי לבד.** הוא עוצר את עצמו, וחוזר רק כשרת גיבוי.

## 2. רשימת ציוד (חובה)

| מה | למה | הערה |
|---|---|---|
| **UPS** לשרת A, לשרת B, למתג ולנקודות הגישה (WiFi) | הפסקת חשמל לא מפילה את הרשת | לפחות 30 דקות. חיבור USB לשרת A (וגם ל-B אם יש שני UPS) |
| **שני שרתים** (מחשב קטן מספיק: 8GB זיכרון, דיסק SSD) | אחד ראשי, אחד גיבוי | אם אפשר, **כל אחד בארון או בשקע אחר** |
| **שתי נקודות גישה WiFi** שמכסות את כל התחנות | אם אחת נופלת, הטאבלטים עוברים לשנייה | אותו שם רשת (SSID) ואותה סיסמה |
| **מתג (switch)** | מחבר את השרתים ואת נקודות הגישה | על ה-UPS |
| **דיסק חיצוני (USB)** בשרת A וגם בשרת B | גיבוי לילי שנבדק | הגיבוי נעשה בשרת שהוא הראשי באותו לילה |

**כתובות קבועות:** לשרת A, לשרת B ולכתובת הצפה. כולן מחוץ לטווח ה-DHCP של הנתב.

## 3. התקנה (פעם אחת)

על **שני** השרתים:

```bash
sudo apt install postgresql-16 keepalived nut iputils-ping
sudo mkdir -p /opt/glatttrack /etc/glatttrack
sudo cp -r plant-server /opt/glatttrack/
sudo cp /opt/glatttrack/plant-server/gt-plant.conf /etc/glatttrack/gt-plant.conf
sudo nano /etc/glatttrack/gt-plant.conf
```

**ב-`gt-plant.conf`:**
- **שלוש השורות הראשונות** (GT_SELF, GT_SELF_IP, GT_PEER_IP) שונות בין A ל-B.
- **שאר השורות** זהות בשני השרתים.
- **שתי סיסמאות חובה, זהות בשני השרתים** (בלעדיהן הכלים מסרבים לרוץ):
  - `GT_REPL_PASS`: לפחות 16 תווים. אפשר ליצור בפקודה `openssl rand -hex 24`.
  - `GT_VRRP_PASS`: 8 תווים אקראיים.
- **הקובץ נשמר כך שרק root יכול לקרוא אותו.** הכלים דואגים לזה לבד.

### 3.1 שרת A (ראשי). GlattTrack כבר מותקן ועובד עליו

```bash
sudo /opt/glatttrack/plant-server/setup-primary.sh
sudo systemctl restart postgresql
```

### 3.2 שרת B (גיבוי)

```bash
sudo /opt/glatttrack/plant-server/setup-standby.sh --yes
```

הפקודה **מוחקת** את מסד הנתונים של B ומעתיקה את כולו מ-A. בסוף צריך להופיע `standby B: standby`.

### 3.3 הכתובת הצפה (keepalived), על שני השרתים

```bash
sudo /opt/glatttrack/plant-server/keepalived/make-keepalived.sh
sudo systemctl enable --now keepalived
```

הקובץ נכתב לבד מתוך `gt-plant.conf`. רק השרת שהוא ראשי יכול להחזיק את הכתובת.

### 3.4 שומר הסנכרון והגיבוי הלילי, על שני השרתים

```bash
sudo cp /opt/glatttrack/plant-server/systemd/* /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now gt-sync-watchdog.service gt-backup.timer
```

### 3.5 UPS (NUT), על כל שרת שה-UPS מחובר אליו ב-USB

1. מגדירים את NUT לפי סוג ה-UPS (`/etc/nut/ups.conf`).
2. מוסיפים ל-`/etc/nut/upsmon.conf` את השורות מ-`nut/upsmon-snippet.conf`.

### 3.6 בדיקה שהכל עובד

במסך **בריאות מערכת** של ראש הצוות צריך לראות:

* 🟢 **שרתים:** `שרת A · שרת גיבוי: מחובר`
* 🟢 **חשמל (UPS):** `תקין`
* 🟢 **גיבוי:** `מאומת לפני … שעות`

## 4. שתי החלטות של המפעל (חשוב לקרוא)

### 4.1 כששרת הגיבוי נופל: להמשיך לעבוד, או לעצור? (`GT_SYNC_MODE`)

| מצב | מה קורה כש-B נופל | הסיכון |
|---|---|---|
| **`available`** (ברירת מחדל) | אחרי כ-6 שניות A ממשיך לבד. **העבודה לא נעצרת.** | פסיקות שנעשו בזמן ש-B כבוי שמורות **רק ב-A**. אם גם הדיסק של A נהרס לפני ש-B חוזר, הן אובדות. |
| **`strict`** | פסיקה מאושרת **רק** כששני השרתים מחזיקים אותה. כש-B כבוי, **העבודה נעצרת** (הטאבלטים ננעלים) עד שהוא חוזר. | אין אובדן, אבל עצירה. |

**עד הגרסה הזו כתבנו "אין אובדן פסיקה" בלי הסתייגות. זה נכון רק כששני השרתים פועלים, או במצב `strict`.**

### 4.2 החלפת השרת הראשי: ידנית או אוטומטית? (`GT_AUTO_PROMOTE`)

**למה לא אוטומטית?** אם רק הכבל שבין A ל-B נקרע, כל שרת חושב שהשני מת. אם B היה משתלט לבד, היו שני שרתים ראשיים ושתי "אמיתות". פסיקות שנרשמו באחד מהם היו הולכות לאיבוד כשהם מתחברים שוב.

* **`0` (ברירת מחדל): ידני.** כש-A נופל, הטאבלטים ננעלים ("אין שרת"). מישהו בודק ש-A באמת כבוי (מכבה אותו או מוציא לו את כבל הרשת), ואז מריץ על B:
  ```bash
  sudo /opt/glatttrack/plant-server/takeover.sh      # מבקש להקליד OFF לאישור
  ```
  B הופך לראשי ומקבל את הכתובת, והטאבלטים נפתחים לבד.
* **`1`: אוטומטי.** אפשרי רק עם **מכשיר שלישי ("עד")** שמכריע מי חי. עוד לא קיים בערכה. אם רוצים, אבנה אותו בהמשך.

## 5. מה קורה כש...

| מקרה | מה קורה לבד | מה רואים במסך הבריאות | מה עושים |
|---|---|---|---|
| **הפסקת חשמל** | הכל ממשיך על ה-UPS | 🔴 חשמל: על סוללה | להכין את נוהל החירום אם החשמל לא חוזר |
| **סוללה נמוכה** | השרתים נכבים מסודר | 🔴 סוללה כמעט ריקה | לפי נוהל החירום |
| **שרת B נפל** | `available`: A ממשיך לבד אחרי כ-6 שניות. `strict`: העבודה מחכה ל-B | 🔴 שרתים: שרת גיבוי לא מחובר | לתקן את B. כשהוא חוזר, הסנכרון חוזר לבד |
| **שרת A נפל** | הטאבלטים ננעלים. **B לא משתלט לבד** | — | לוודא ש-A כבוי, ואז להריץ `takeover.sh` על B |
| **הכבל בין A ל-B נקרע** | שום דבר לא מתחלף. A ממשיך כראשי | 🔴 שרת גיבוי לא מחובר | לחבר את הכבל |
| **A חזר לבד אחרי החלפה** | A רואה ש-B ראשי, **עוצר את עצמו**, ולא מקבל את הכתובת | — | סעיף 6 |
| **נקודת גישה אחת נפלה** | הטאבלטים עוברים לשנייה | — | להחליף |
| **המתג נפל** | אין רשת, הטאבלטים ננעלים ("אין שרת = אין עבודה") | — | מתג רזרבי במחסן |

## 6. החזרת שרת ישן כשרת גיבוי (אחרי החלפה)

על **השרת הישן**:

```bash
sudo /opt/glatttrack/plant-server/rejoin-as-standby.sh --yes
```

- **מה הפקודה עושה:** מוחקת את הנתונים הישנים של השרת ומעתיקה הכל מהראשי החדש.
- **אחרי כמה שניות** מסך הבריאות חוזר ל-🟢 **שרתים: שרת גיבוי מחובר**.

## 7. הגיבוי הלילי: איך יודעים שהוא באמת טוב (v10.16)

כל לילה הגיבוי **משוחזר במלואו** לתוך מסד בדיקה, ונחשב תקין **רק אם:**

* **השחזור עבר בלי שום שגיאה.**
* **שלב השרת** בעותק זהה לשרת החי.
* **מספר האירועים** בעותק הוא לפחות מה שהיה כשהגיבוי התחיל.
* **שרשרת יומן האירועים** בעותק שלמה.

אחרת יופיע במסך הבריאות 🔴 **גיבוי: הבדיקה האחרונה נכשלה**, עם הסיבה.

## 9. קבצים

| קובץ | מה הוא עושה |
|---|---|
| `gt-plant.conf` | ההגדרות של השרת, כולל שתי ההחלטות מסעיף 4. מעתיקים ל-`/etc/glatttrack/` |
| `setup-primary.sh` | פעם אחת, על הראשי |

| `systemd/`, `nut/` | הפעלה אוטומטית |
